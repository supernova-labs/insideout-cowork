# Publicação e acesso do snapshot

Use Sites apenas para hospedar o snapshot estático de revisão. A base
**InsideOut Social** continua sendo a fonte de verdade.

## Publicar sem convidar

1. Gere e valide o HTML completo.
2. Crie ou reutilize o Site correspondente sem adicionar visitantes.
3. Publique a versão com acesso restrito ao proprietário.
4. Verifique que a publicação concluiu e que o acesso continua restrito.
5. Entregue o link ao proprietário e informe que nenhum cliente foi convidado.

Publicar e liberar acesso externo são ações distintas. Não torne o Site público
para evitar autenticação: o grid pode conter estratégia de comunicação do
cliente.

## Liberar visitantes externos

Somente quando o usuário pedir essa mudança:

1. obtenha a lista exata de emails autorizados;
2. mostre a política atual e a lista proposta;
3. avise que a plataforma pode enviar uma notificação de convite ao aplicar o
   acesso customizado;
4. peça confirmação explícita para essa lista;
5. configure acesso `custom` somente para o proprietário e os emails aprovados;
6. releia a política de acesso antes de declarar sucesso.

O link pode ser compartilhado manualmente numa reunião depois que os emails
estiverem autorizados. Não prometa senha compartilhada, acesso anônimo ou um
método de autenticação que Sites não ofereça na sessão.

## Limites

- nenhuma publicação aberta à internet;
- nenhum email adicionado por inferência, agenda ou domínio da empresa;
- nenhum formulário, upload, comentário persistente ou escrita no snapshot;
- nenhuma mudança de acesso junto com a primeira publicação;
- nenhuma alegação de acesso validado sem reler a política do Site.
